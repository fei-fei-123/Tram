# Tram 宿主页 · 域模型（词表草案）

> 2026-11-09。背景：架构分了层（宿主/引擎/插件），但缺"名词"，实现无法下手。本文补词表：
> 先定名词（域对象），再定动词（服务操作），事件跟着动词走。
> **纪律：后续每个新概念，按"字段 / 属主 / 操作 / 事件"四栏格式补进本文，禁止在代码里私造概念。**

## 词表映射（2026-11-09 定）

- **slot（槽）**：业务名词，面向叙事——页面文案、插件文档、跨会话沟通。指程序预留的、可被占用的位置（引擎的站、UI 的锚点、插件的位置皆是槽）。
- **filter（滤器）**：实现名词，面向代码——引擎、测试、配置里用。槽的实现形态，按形态.md：filter ＝ (ctx, chain) 函数。
- 规则：**业务说 slot，代码说 filter**，一一对应；同一事物两个语境各用一个词，不混用。

## 全景数据流

```
用户输入
 → MessageService.append(role=user)            # 落库 + 广播
 → TurnService.start(session)                  # 建 Turn
     组装 ctx（会话近期消息投影 + system + meta）
 → 引擎跑链（滤器们改 ctx）                     # 引擎层，契约见 形态.md
 → 链出口 content
 → MessageService.append(role=agent)           # 落库 + 广播
 → turn.finished                               # 页面与插件从事件流各自跟进
```

## 名词

### Message（消息）

| 字段 | 类型 | 属主 | 说明 |
|---|---|---|---|
| id | str | 系统 | `msg_<uuid>`，全局唯一，不可变 |
| session_id | str | 系统 | 所属会话 |
| role | enum | 系统 | `user / agent / plugin` |
| content | str | 系统 | 一期纯文本/Markdown |
| attachments | list | 预留 | 二期 |
| meta | dict | 插件自由区 | 读自由；写须经 API |
| edited | bool | 系统 | 被编辑过 |
| created_at | datetime | 系统 | |

**不可静默改**：改＝edit API（覆盖 content＋置 edited 标记），删＝delete API；
每次操作必广播事件。UI 与插件只认事件之后的当前状态。

### Session（会话）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | str | `sess_<uuid>` |
| title | str | 侧栏显示名 |
| status | enum | `active / archived` |
| meta | dict | |
| created_at | datetime | |

会话是**身份与元数据**，不是消息容器本身——消息按 session_id 附属查询。
一个会话同一时刻至多一个进行中的 Turn。

### Turn（轮次）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | str | `turn_<uuid>` |
| session_id | str | |
| trigger | enum | `user_message / plugin / system` |
| input_msg_ids | list | 本次链的输入消息 |
| output_msg_ids | list | 链产出落库的消息 |
| status | enum | `running / done / failed / cancelled` |
| trace_id | str | 指向引擎 trace（形态.md 的 jsonl） |

Turn 是"程序忙不忙"的唯一事实来源（状态栏、输入框禁用都看它）。

## 动词（服务操作 → 事件）

| 服务 | 操作 | 广播事件 |
|---|---|---|
| SessionService | create / rename / archive / list | session.created / session.updated |
| MessageService | append / edit / delete / get / list | message.appended / message.edited / message.deleted |
| TurnService | start / cancel | turn.started / turn.finished |
| PluginManager | load / unload / enable / disable | plugin.loaded / unloaded / enabled / disabled |
| EventBus | publish / subscribe | —（总线本身） |

页面是事件流的**普通订阅者**（经 websocket）。UI 是第一个插件，没有特权渲染路径。

## 插件改"消息/会话"的三条合法路径

1. **轮前改输入**（引擎层）：注册滤器改 ctx——模型看到的可以和页面显示的不一样
2. **轮后改记录**（宿主层）：订阅 `message.* / turn.*` 事件，调 MessageService.edit
3. **主动发言**：`MessageService.append(role="plugin")`——通知、卡片、定时消息

**禁止直接改存储。** 单一纪律换来：所有变更必经服务 → 必广播 → 页面和所有插件自动跟上。

## 引擎与域模型的关系（缝合形态.md）

- `ctx.messages`（运行时信封）＝从 Session 取近期消息的**投影**；链只产出 content
- content 由宿主落库为 Message——**引擎不认识 Session/Message，域模型是宿主的**
- 一期单实例（一条链）；会话只是消息容器；多实例（每会话不同拓扑）二期再议

## 存储（一期默认）

- SQLite 单文件（stdlib `sqlite3`，无 ORM）：`sessions / messages / plugins`（启停状态）三张表
- trace 沿用形态文档：jsonl 逐行
- 换存储是 Service 内部事，接口不变
