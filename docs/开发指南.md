## 0. 三十秒概览

程序＝**宿主**（页面＋插件体系＋三个服务）内嵌**引擎**（滤器链，机制白清单四件：doFilter 递归／列表装配／deps 口子／trace 写入）。**功能全是插件**——LLM 也是插件。宿主管域对象（会话/消息/轮次），引擎只见 ctx（消息投影）进、content 出。

- 纯标准库实现（sqlite3/urllib/json），无三方运行时依赖；测试要 pytest。
- 无智能环也能跑：echo 兜底滤器保底回话（机制基线）。

## 2. 核心机制（改代码前必读）

### 2.1 滤器与链

滤器＝**裸函数 `filter(ctx, chain)`**：

- 交棒：`return chain.doFilter(ctx)`（继续下游）；
- 短路：不调 `chain.doFilter`（自己负责产出，终止本链）；
- 链尾：所有滤器交棒到底后返回 `ctx.get("content")`——**content 由链上滤器负责产出**。

装配是**单一有序列表**：`[*贡献段, *核心段]`。

- 贡献段：插件经 `add_filter(fn)` **只追加**（注册序即运行序；`at` 参数已废除，位置需求将来走实例配置列表）；
- 核心段：引擎实例配置 `engine_config={"filters": [函数...]}`，**缺省空**；echo 通常由这里注入做兜底。

真机链现在是 `[hello_onion, llm, echo]`：洋葱（改输入→交棒→改输出）包住 llm，echo 兜底（llm 已产出 content，echo 只交棒不覆盖）。

### 2.2 ctx 与 deps（签名永不再扩）

```python
ctx = {"messages": [{"role","content"}...],   # 会话近期消息投影（宿主造）
       "system": "",                          # 宿主管来源；插件滤器可改写（模型看到的≠页面显示的）
       "meta": {"session_id", "turn_id"}}
deps = {"config": {...运行期副本...}, "store": {实例私有，活过单次运行}}
```

滤器取依赖只经 `chain.deps`（白清单 3）。运行期 `deps.config.provider` 上放的是**被追踪包装的 provider**（见 §4.4）。

### 2.3 trace（白清单 4）

`data/traces/trace.jsonl`，逐行 JSON，同轮各行共用 `trace_id`：

```json
{"kind": "llm.round", "turn_id": "…", "round": 1,
 "request": {"messages": [LLM 视图（注入后）]}, "response": {"content": "…"}, …}
{"kind": "run", "turn_id": "…", "messages_in": [投影], "content_out": "…", "rounds": 1, …}
```

provider 调用**失败也留痕**（`error` 字段替代 `response`，且无 run 行）。引擎靠包装 provider 实现“trace 无接口、系统自转”——**这就是 add_provider 槽位存在的唯一理由：观测，不是管理**。

## 3. 一次请求的一生（带文件定位）

1. `TurnService.start(session_id, trigger)`（host/services/turns.py）
   校验 trigger 词表（user_message/plugin/system）→ 互斥（一会话一 running Turn，否则 `TurnRunningError`）→ `list_recent(session, 20)` 取投影 → 建 turn(running) → 广播 `turn.started` → 组 ctx。
2. 取**贡献段** `plugins.chain_filters()` 与**模型槽位** `plugins.provider()`。
3. `Engine.run(ctx, filters=…, provider=…, turn_id=…)`（engine/__init__.py）
   生成 trace_id → provider 不为空则包 `_TracedProvider` → 装配 `[*filters, *core]` → `chain.doFilter(ctx)` → 收尾写 run 行 → 返回 `(content, trace_id)`。
4. 链上过站（现真机：hello_onion → llm → echo）。
5. 回到 TurnService：`MessageService.append(session, "agent", content)`（广播 `message.appended`）→ turn done → 广播 `turn.finished`。
6. 插件对 `turn.finished` 的反应在 finished 广播**之后**发生（订阅者天然滞后一拍）：hello 改记录（`message.edited`）＋主动发言（`message.appended`，role=plugin）。

失败路径：链抛异常 → turn failed → 广播 `turn.finished(status=failed)` → 异常重抛，**不落 agent 消息**。取消：`cancel()` 置 cancelled，链结果作废不落库（同步引擎拦不住链本身，真中断待 B 后续/异步）。

## 4. 插件体系

### 4.1 契约

- `manifest.json`：必填 `id`（`^[a-z][a-z0-9_-]*$`）/`name`/`version`；可选 `entry`（默认 plugin.py）、`anchors`（声明元数据，暂未强制校验）、`events`（声明订阅，start 时自动接线到 `on_<event>` 方法，如 `turn.finished`→`on_turn_finished(ctx, event)`；缺方法只告警）、`config`（插件自管配置，原样进 `ctx.config`）。
- `plugin.py`：暴露 `create_plugin() -> Plugin 实例`（须继承 `host.plugins.base.Plugin`）。

### 4.2 生命周期与贡献撤销

`load`（读 manifest→import→on_load）→ `start`（自动订阅＋on_start）→ `stop`／`unload`／`enable`／`disable`。启停状态持久在 plugins 表（新插件默认 enabled=1；重载不覆盖用户的停用决定）。

**贡献按作用域撤销**：on_start 里产生的（滤器/订阅/卡片/provider）随 `stop` 收回；on_load 里的随 `unload` 收回；`store` 是插件私有持久物，卸载不清。`ui.add_*`／`events.subscribe`／`agent.add_filter`／`agent.add_provider` 都返回 Handle（dispose 幂等）。

### 4.3 PluginContext 七口子（ctx）

| 口子 | 用途 |
|---|---|
| `ctx.agent` | **add_filter(fn)** 只追加注册滤器；**add_provider(p)** 上交模型运行时进槽位；get_message / edit_message（路径 2 写手）/ speak（路径 3，role=plugin）/ start_turn |
| `ctx.events` | subscribe(topic, fn) 订阅宿主事件流（路径 2 的听筒） |
| `ctx.ui` | add_card(标题, 正文, placement) 声明式卡片，宿主渲染 |
| `ctx.store` | 插件私有持久 kv（json 文件 data/plugin_stores/&lt;id&gt;.json） |
| `ctx.config` | 只读，manifest 的 config 节（**LLM 配置自管就在这**） |
| `ctx.status` | set/get 状态文案（管理页显示用） |
| `ctx.log` | logging.getLogger(f"tram.plugin.&lt;id&gt;") |

### 4.4 LLM 插件的特别之处：配置自管＋槽位＝观测

`plugins/llm/manifest.json` 的 config 节放着 base_url/model/api_key/timeout——**宿主与引擎都不读它**。on_start 时插件自己 `build_provider(ctx.config)` 构造 `OpenAICompatProvider`，经 `agent.add_provider(p)` 上交宿主**单槽**（后上交替前；Handle 撤销即出槽）。引擎 run 时把槽位上的 provider 包一层 `_TracedProvider` 放进 `deps.config.provider`——**槽位是观测口（记逐轮 trace），不是管理口**：宿主不配、不建、不节制 provider。

llm 滤器本体（23 行）从槽位取 provider：`chain.deps["config"]["provider"]` → `llm_view(ctx)`（system 非空注入打头）→ `provider.chat(msgs)` → `ctx["content"]=resp["content"]` → 交棒。**没 provider 时抛 EngineError（中文提示）**。

换模型＝改 `plugins/llm/manifest.json` 一行；换协议＝新 Provider 适配器（engine/providers.py 加类，照 OpenAICompatProvider 形状：`chat(messages) -> {"content": str}`，失败抛异常）。

### 4.5 现成插件

- **hello**：路径 1（洋葱滤器：下沉给最后一条 user 加 `·hello-sink` → 交棒 → 上浮加 `[hello-onion HH:MM:SS]` 时间戳）＋路径 2（订阅 turn.finished，给产出消息加 `[hello-edit]`）＋路径 3（主动发言“…（第 N 次）”，N 存 ctx.store）。
- **llm**：见 §4.4。

## 5. 服务与事件（一切变更必经服务→必广播）

| 服务 | 动词 | 事件 |
|---|---|---|
| SessionService | create / rename / archive / list / get | session.created / session.updated(changed:["title"|"status"]) |
| MessageService | append / edit / delete / get / list / list_recent | message.appended / message.edited / message.deleted |
| TurnService | start / cancel | turn.started / turn.finished(status=done/failed/cancelled) |
| PluginManager | load / unload / enable / disable（start/stop 无事件） | plugin.loaded / plugin.unloaded / plugin.enabled / plugin.disabled |
| EventBus | publish / subscribe | —（总线本身） |

payload 形状：`{"session": {...}}`／`{"message": {...}}`／`{"turn": {...}}`／`{"message_id", "session_id"}`／`{"plugin_id", …}`。event 信封：`{"type", "ts", "payload"}`。页面（C 阶段 websocket）是普通订阅者，无特权路径。

role 词表：`user / agent / plugin`（一期无 system 通知类）；trigger 词表：`user_message / plugin / system`。

## 6. 存储

`data/tram.db`（stdlib sqlite3，无 ORM，单连接＋锁）：

- `sessions(id, title, status, meta, created_at)`
- `messages(id, session_id, role, content, attachments, meta, edited, created_at)`
- `plugins(id, enabled, meta)`

**Turn 不落库**（运行态在 TurnService 内存 `_running`，历史 Trace 靠 jsonl）；插件私有 kv 走 json 文件不占表。改存储是 Service 内部事，接口不变。

## 8. 动手改：常见场景

**写新插件**：plugins/ 下建目录 → manifest.json（照 hello/llm 抄骨架，id 唯一）→ plugin.py（`create_plugin()` 返回 Plugin 子类）→ 行为写在生命周期里，贡献全部经 ctx 口子（自动可撤销）→ `python -m pytest` 加你自己的用例（可用 tmp 插件仓模式）。

**微调模型行为**：改 `plugins/llm/manifest.json`（model/base_url/timeout）；改提示词注入逻辑＝改 llm 插件的 `llm_view`；想加“响应侧后处理”＝再写一个插件 add_filter（它会排在 llm 后面——注册序）。

**加引擎机制**：先对照形态.md 白清单——不在四件内的机制不要进 engine/，优先做成插件滤器。

**注意**：写代码含 key/token 样式字面量（sk-…之类）可能被工具管道脱敏截断——测试与示例用假值（如 "test-key"）。

## 9. 设计裁决记录（为什么代码长这样）

1. **词表映射**：业务说 slot，代码说 filter，一一对应（域模型.md）。
2. **add_filter(fn) 单签名**：删 at 参数，只追加；位置需求将来走实例配置列表。
3. **单一有序列表**：贡献段（注册序）＋核心段（实例配置）；无 pre/post 分桶。
4. **LLM＝插件，配置自管**：manifest config 节，程序不代管 provider 配置值。
5. **add_provider 槽位＝观测口非管理口**：宿主只包一层记逐轮 trace（机制 4 的物理载体）；插件不配、不建、不节制。
6. **echo 兜底**：content 已产出不覆盖——无智能环宿主的机制基线。
7. **Turn 不落库**：运行态内存＋trace jsonl（要历史 Turn 先补域模型四栏）。
8. **订阅者异常向上抛**（fail loud），无隔离——坏插件会打断派发（B 后续再议）。
9. **插件滤器恒在核心段前**（贡献段在前）：hello 洋葱天然包住 llm。
